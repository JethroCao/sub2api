# OpenAI 非文本请求错误诊断日志设计

## 背景

杭州节点的 OpenAI Responses 请求被调度到标记为 `text_only` 的火山 DeepSeek 账号后，上游返回 `Model only support text input`。现有图片输入检测只扫描已知的 `input_image`、`image_url` 以及 `input/messages` 下的 `content`，但线上错误发生后没有保留原始请求结构，无法确认漏判的是图片、文件、截图工具输出还是其他非文本条目。

## 目标

仅在上游明确返回非文本输入不受支持的 400 错误时，记录客户端入口请求和实际发送给上游的完整 JSON，为后续补齐检测规则提供证据。正常请求和其他错误不得记录请求体。

## 命中条件

诊断器只处理 HTTP 400，并匹配以下上游错误消息（忽略大小写）：

- `Model only support text input`
- `Model do not support image input`

结构化错误码或参数作为附加元数据记录，但不单独扩大匹配范围，避免误记录无关请求。

## 日志内容

每次命中输出两条 Warn 日志，使用统一事件名 `openai.non_text_input_request_body`：

1. `body_kind=client`：进入网关时的客户端原始 JSON。
2. `body_kind=upstream`：模型映射、兼容转换和字段清理后，实际发送给失败账号的 JSON。

每条日志同时记录：

- 请求上下文中的 request ID
- account ID 和账号名称
- API Key ID
- 上游 HTTP 状态码、错误码、错误参数和错误消息
- 原始模型和上游模型
- 请求体字节数
- 请求体 SHA-256
- 完整请求体

日志沿用现有请求上下文，不写数据库、不写临时文件，并标记为跳过运维系统日志入库，避免大请求体进入管理后台数据库。

## 代码结构

新增独立诊断模块，负责：

- 判断是否为目标错误；
- 生成公共元数据；
- 分别记录 client/upstream 请求体。

在 OpenAI HTTP 转发的上游错误处理处调用，位置与现有 `partial` 缺参诊断相邻。诊断代码不得修改请求体、重试策略、账号状态或客户端响应。

## 测试

覆盖以下场景：

- 两种目标错误均命中；
- 非 400、其他 400 错误和仅包含普通 `text input` 字样的消息不命中；
- 命中时恰好记录 client/upstream 两条日志；
- 两条日志包含完整正文、长度、SHA-256、账号、Key 和模型元数据；
- 网关集成测试确认模型映射后的上游正文与入口正文分别被记录；
- 诊断行为不改变原有错误响应。

## 上线与后续

构建并部署到杭州 `120.55.76.195`、`121.41.9.209`。等待下一次目标错误后，按 request ID 提取两条日志并比较 input 条目类型。确认真实漏判结构后，另行编写最小修复及回归测试；本次变更不猜测或提前扩展图片检测规则。
